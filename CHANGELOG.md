# История изменений

Формат по [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/); версионирование
семантическое (мажор.минор.патч). Версия web-интерфейса отображается в футере страницы.

## [0.7.1] — 07.09.2026

### Исправлено
- **Настройки веб-поиска из UI игнорировались**: провайдер sonar создавался
  реестром без аргументов и брал алиас модели, роутер и API-ключ из глобального
  config.yaml/.env — выбор поисковой модели в веб-форме (и даже другой роутер
  сессии) не действовал. Теперь `LegalResearchService.configure(cfg)` применяет
  конфиг сессии к провайдерам перед research (регрессия покрыта тестами:
  сессионный алиас побеждает yaml; креденшелы — из сессии).

## [0.7.0] — 07.09.2026

### Добавлено
- **Авторетрай транзитных сбоев LLM в `chat()`** (`src/llm_client.py`): пустой
  ответ роутера (стрим закрыт без контента — в т.ч. только reasoning-поля) и
  ошибки API до начала генерации (таймаут/обрыв, 429, 5xx) повторяются до 2 раз
  (паузы 2/5 с). Частичный стрим (контент уже ушёл в UI) и неповторяемые ошибки
  (401/403/400) не ретраятся. При исчерпании попыток сообщение об ошибке содержит
  диагностику: finish_reason, объём reasoning-дельт, токены, число попыток.
  Раньше один пустой ответ модели обрывал всю симуляцию (кейс сессии
  `fa72dc86c917`, модель `~anthropic/`).
- **Human-in-the-loop: запросы доказательств судом**. Новый маркер
  `=== РЕШЕНИЕ СУДЬИ: ТРЕБУЕТСЯ ДОКАЗАТЕЛЬСТВО: <что требуется> ===` — когда исход
  дела критически зависит от отсутствующего доказательства (экспертиза, показания
  свидетеля, банковская выписка). Прения встают на паузу, в UI открывается
  контекстное окно: текст запроса суда + поле «Что показало доказательство»;
  кнопки «Представить» / «Не представлять». Ответ приобщается к материалам дела
  как запись суда и учитывается всеми агентами в следующих раундах и в вердикте.
  Таймаут ожидания — 10 минут; лимит — 2 запроса за процесс; в отчёте новый
  раздел «Запросы доказательств в ходе процесса».
- API: `POST /api/session/{id}/evidence-answer` — ответ на запрос суда
  (409, если запроса нет/уже отвечен).
- API: `POST /api/setup` принимает `web_search` и `search_model` — настройки
  веб-поиска из формы применяются к сессии.

## [0.6.0] — 07.09.2026

### Добавлено
- **Fulltext-сверка источников** (`src/legal/fulltext.py`, `legal_research.fulltext_verify`):
  страница источника скачивается по `official_url`, текст извлекается markitdown
  (HTML и PDF), при совпадении ≥2 реквизитов (номер акта, дата — в т.ч. текстовый
  формат, номер статьи) выдержка заменяется реальной цитатой; официальные домены
  (pravo.gov.ru, vsrf.ru) поднимаются до `verified`, неофициальные (sudact) остаются
  `partially_verified` с выдержкой. Ошибки → источник без изменений. Проверено
  живьём: постановление Правительства на publication.pravo.gov.ru → verified.
- **Веб-поиск в UI**: чекбокс «⚖ Веб-поиск правовых источников» и алиас поисковой
  модели (с пресетами) в форме «Настройка» — применяются к сессии (раньше настройки
  читались только из config.yaml).
- **Плагин web routerai**: запрос sonar ограничен `max_results: 5` и
  `include_domains` официальных источников — меньше поискового контекста (он
  тарифицируется отдельно) и меньше шума; парсинг стал надёжнее — сначала
  структурированные аннотации `url_citation`, текстовые форматы в резерве.
- **Честная цена поиска**: в отчёте и UI предупреждение «вызовы веб-поиска
  (legal_research) тарифицируются роутером отдельно от токенов — фактическое
  списание может быть выше показанной суммы».

## [0.5.0] — 07.09.2026

### Добавлено
- **Веб-поиск правовых источников** (`sonar_web_search`): провайдер на базе
  поисковой модели роутера (по умолчанию `perplexity/sonar-pro-search`,
  алиас настраивается) — находит действующие НПА РФ и правоприменительную
  практику (Пленум/Президиум ВС, обзоры, решения судов) в одном запросе
  LLM+поиск. Ссылки фильтруются белым списком официальных доменов
  (pravo.gov.ru, vsrf.ru, sudact и др.); результаты всегда
  `partially_verified` с предупреждением о сверке; потребление пишется
  в таблицу ресурсов с ролью `legal_research`. Трёхуровневый парсер ответа:
  строгий формат «реквизиты | URL | суть» → markdown-ссылки → URL в прозе.
- **Конфигурация правового исследования** (`config.yaml` → `legal_research`):
  `web_search` (вкл/выкл веб-поиска, по умолчанию включён) и `search_model`
  (алиас поисковой модели; приоритет: config → env `SONAR_MODEL` → дефолт).
- **Переквалификация дела судьёй**: новый маркер
  `=== РЕШЕНИЕ СУДЬИ: ПЕРЕКВАЛИФИКАЦИЯ: <новый характер спора> ===` — если в
  прениях выяснилось, что характер спора изменился (пример: товар использовался
  для извлечения коммерческой прибыли → ЗоЗПП неприменим), граф возвращается
  в узел `build_evidence_pack` и пересобирает Evidence Pack с запросом,
  расширенным причиной переквалификации и последними репликами; прения
  продолжаются в рамках `max_rounds`. Лимит — 2 переквалификации за процесс
  (`MAX_REQUALIFICATIONS`); причины и число проходов попадают в отчёт.
- **UI**: баннер «⚖ Идёт подготовка законодательной базы…» с живым счётчиком
  найденных источников — показывается при каждом проходе правового исследования
  (в т.ч. повторном после переквалификации); плашка решения судьи различает
  ПЕРЕКВАЛИФИКАЦИЮ с причиной.
- **Валюта прайсов**: для routerai цены отображаются в рублях (₽) — поле
  `currency` в `cost_summary` (символ в UI и таблице потребления);
  для остальных роутеров — доллары ($).
- Отчёт: строка «⚖ Дело переквалифицировано в ходе прений» в параметрах.

### Исправлено
- **NameError `service`** в узле `build_evidence_pack` (`LegalResearchService`
  создавался во вложенной функции и был невидим healthcheck-форвардеру) — из-за
  него правовое исследование молча деградировало: пустой Evidence Pack,
  предупреждение «подтверждённых источников нет» на каждой реплике и 409 на
  `/api/session/{id}/evidence`.
- **NameError `citation_results`** в узлах `final_verdict`/`recommendations`
  (append к несуществующей переменной вместо возврата через reducer) — падение
  в самом конце прений, после всей генерации.
- **Дублирование предупреждения** о неподтверждённых источниках: текст
  предупреждения больше не содержит префикс роли/раунда — дедуплицируется
  в одну строку отчёта.
- **Новости vsrf.ru в судебной практике**: новостные карточки (трансляции,
  пресс-релизы о встречах) отфильтровываются парсером Пленума; пустой запрос
  больше не тащит «всё подряд» у реальных провайдеров.

### Тесты
- 105 → **129**: e2e полного графа с замоканными агентами (обе секции linter,
  переквалификация с пересборкой pack), парсер переквалификации, провайдер
  sonar (парсер ответа, белый список, честная верификация, ошибки), валюта
  cost_summary.

## [0.4.0] — 06.09.2026

### Добавлено — надёжный legal research layer (этап 3)

- **Сменяемый слой провайдеров** `src/legal/`: контракт `LegalProvider`
  (healthcheck / search_statutes / get_document / search_case_law), сервис
  `LegalResearchService` (priority, таймауты, дедупликация, ранжирование),
  доменные модели `LegalSource` / `EvidencePack` / `ProviderHealth`
  (инвариант: `verified=True` только с точной выдержкой и статусом `verified`).
- **Провайдер pravo.gov.ru**: официальный API публикации
  (`/api/Documents` → реквизиты + `eoNumber` → страница `/document/<eoNumber>`);
  тексты статей добираются через markitdown (Microsoft) — цепочка честно помечена:
  реквизиты подтверждены порталом, текст из неофициального источника.
- **SupremeCourtOfficialProvider (vsrf.ru)**: постановления Пленума, обзоры
  практики, опубликованные документы; уровень авторитетности A.
- **Судебная практика из материалов пользователя**: загруженные акты
  классифицируются (`classify_user_document`), извлекаются суд/дата/номер дела/
  инстанция/нормы; уровень `USER` — не считаются внешне подтверждёнными.
- **CaseLawCoverage**: searched/not_searched/coverage + понятные предупреждения;
  «практика не найдена» только после успешного поиска по подключённому источнику.
- **Citation verifier**: проверка ссылок в вердикте/рекомендациях против
  Evidence Pack (ст. N / N-ФЗ / номера дел / [LAW-XXX]); один repair-pass;
  раздел «Проверка правовых ссылок» в отчёте.
- **Диагностика**: `python -m src.legal_diagnostics` (+`--json`, `--provider mock`)
  и `POST /api/legal/diagnostics`; `/api/legal/health`; `/api/session/{id}/evidence`.
- **UI**: секция «Правовые источники (Evidence Pack)» на финальном экране —
  карточки LAW/CASE/DOC со статусами, выдержками, кнопкой «Открыть первоисточник»,
  баннером деградации и статусами провайдеров.
- **Уровни авторитетности**: A (КС/Пленум ВС/обзор ВС), B, C, D, USER.
- Дисклеймер в каждый отчёт (информационно-аналитическая симуляция, не юр. заключение).
- Тесты: 85 → 105 (unit на модели/сервис/верификатор/case-law, замоканные
  провайдеры и MCP-сессии).

### Отключено по умолчанию (точки расширения)
- `SudactPlaywrightProvider`/массовые источники практики: sudact.ru требует
  JavaScript, kad.arbitr — капча; автоматический доступ не включается, Chromium
  в install.bat не добавляется. Доступны только disabled-заготовки
  (`AtomnoCaseLawProvider`, `KadArbitrProvider` — NotImplementedError).

## [0.3.0] — 06.09.2026

### Добавлено
- **Остановка генерации**: кнопка «⏹ Остановить» в прямом эфире → `POST /api/stop/{id}` →
  кооперативная остановка графа (флаг `threading.Event` проверяется узлами перед каждым
  LLM-вызовом); сессия переходит в статус `stopped`, интерфейс возвращается к материалам
  дела, материалы можно дополнить и перезапустить. Ограничение: текущая реплика доигрывается
  (гранулярность — между вызовами).
- **Учёт токенов и денег**: `TokenUsage` парсит usage из финальных событий стрима
  (форматы `prompt_tokens`/`input_tokens` и details по кэшу/reasoning); `chat()` возвращает
  `LlmResult` (наследник `str` + usage) — существующий код агентов не изменён;
  `GET /models` роутера даёт прайсы (`prompt`/`completion`/`input_cache_read` за токен,
  кэш 1 час); `estimate_cost` считает по модели конкретного вызова.
- Живой бейдж «🪙 N токенов · M вызовов» в прямом эфире; карточка «Потребление ресурсов»
  на финальном экране (таблица по вызовам с ценами); секция в md-отчёте; строка в CLI;
  `cost_summary` в JSON-отчёте.

### Проверено
- Живой e2e с тремя разными моделями на ролях (GLM Flash / Qwen 3.8-max / Kimi):
  per-role usage и прайсы корректны; известный дефект данных routerai — алиасы
  `~anthropic/*` отдаются без имени модели (19 записей с одинаковыми ключами), прайс
  для них находится, но может соответствовать не той модели линейки.

## [0.2.0] — 06.09.2026

### Добавлено
- **Веб-интерфейс** (Next.js 16, App Router, TS, Tailwind): 4-шаговый мастер — Настройка
  (пресеты моделей, юрисдикция, target_side) → Загрузка дела (drag-and-drop + контекст) →
  Прямой эфир прений (стриминг, «печатает…») → Итог (вердикт + выделенный блок рекомендаций,
  подтверждённые нормы, экспорт .md/печать в PDF).
- **FastAPI-бэкенд** (`src/api.py`, `src/session_store.py`): сессии в памяти с изолированными
  каталогами `sessions/<id>/`; REST (`/api/setup`, `/api/upload`, `/api/run`, `/api/defaults`,
  `/api/health`, отчёты md/json/download) и `WS /ws/session/{id}` с буферизацией событий
  (replay при переподключении).
- **Событийный протокол** `DebateEvent` в графе: единый sink для консоли и WebSocket;
  legacy-колбэки CLI сохранены.
- **Блок рекомендаций для стороны** (агент-аналитик после вердикта): сильные/слабые места,
  риски, правки текста ответа на претензию, качественный прогноз (`ПРОГНОЗ:` маркер);
  выбирается пользователем (`target_side`).
- **Актуальные нормы права через MCP**: `src/legal_tools.py` — клиент `pravo-mcp`
  (pravo.gov.ru, stdio, без API-ключей); перед репликой модель формулирует запросы
  (название/номер акта) → поиск → блок «ПРОВЕРЕННЫЕ НОРМЫ» в промпт; деградация с
  предупреждением в отчёте. Пакет `pravo-mcp` ставится из локального wheel (`wheels/`).
- **`install.bat`**: установка для пользователя без техфона (Python/Node check, venv,
  зависимости, интерактивный ключ, сборка фронта, запуск двух окон, браузер).
- Ключ API из `.env` подставляется, если не введён в форме (`GET /api/defaults` —
  преднастройки из config.yaml, маска ключа); автогенерация контекста дела из загруженных
  документов; умная карточка конфигурации вместо формы; кнопки «← Назад»; индикатор бэкенда.
