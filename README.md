# Судебный симулятор (court-simulator, MVP)

CLI-приложение, эмулирующее судебный процесс: три LLM-агента — **юрист заявителя**,
**юрист ответчика** и **судья** — ведут прения по конкретному делу пользователя в
несколько раундов, после чего судья выносит итоговое мотивированное решение.

Оркестрация — **LangGraph** (state machine с условными переходами; судья-супервизор
решает, когда прения заканчиваются). Вывод — стриминг реплик в консоль (rich) и
полный markdown-протокол в файл. LLM — любой OpenAI-совместимый роутер
(routerai.ru, OpenRouter, LiteLLM, vLLM, OpenAI), модель выбирается **отдельно для
каждой роли**.

## Как это работает

```
START → init → claimant_turn → defendant_turn → judge_review ──┐
                   ↑                                           │
                   └── (судья: ПРОДОЛЖАТЬ и раунды < max) ──────┤
                                                               └─→ final_verdict → END
```

- **init** — загрузка конфига и материалов дела, подготовка состояния.
- **claimant_turn / defendant_turn** — реплики юристов: каждый видит всю историю
  прений и опирается только на факты из материалов дела (со ссылками на источники).
- **judge_review** — судья *не спорит*: оценивает аргументы и решает — задать
  уточняющий вопрос стороне/сторонам (машиночитаемый маркер
  `=== РЕШЕНИЕ СУДЬИ: ПРОДОЛЖАТЬ (кому: claimant_lawyer|defendant_lawyer|both) ===`)
  или завершить процесс (`ЗАВЕРШИТЬ`). `max_rounds` из конфига — жёсткий предохранитель.
- **final_verdict** — мотивированное решение: установленные обстоятельства, оценка
  позиций сторон, правовое обоснование, резолютивная часть, судебные расходы.

Юрисдикция из конфига подставляется во все системные промпты: для РФ это ГК РФ,
ГПК/АПК и профильные законы (например, ЗоПП) с прямым запретом выдумывать номера
статей. Каждое обращение к LLM логирует роль, модель и роутер (видно с флагом `-v`).

## Требования

- Python **3.11+** (разрабатывался и тестировался на 3.14)
- API-ключ OpenAI-совместимого роутера

## Установка

Windows (PowerShell):

```powershell
git clone <URL-репозитория>
cd russianlawbattle
py -3.14 -m venv .venv                # или py -3.11/-3.12, либо python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Linux / macOS:

```bash
python3.12 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

## Настройка

```powershell
Copy-Item .env.example .env                # 1) ключ API
Copy-Item config.yaml.example config.yaml  # 2) роутер, модели, юрисдикция
```

В `.env` положите ключ (имя переменной должно совпадать с `api_key_env` в конфиге):

```ini
ROUTERAI_API_KEY=sk-...             # routerai.ru
# OPENROUTER_API_KEY=sk-or-v1-...   # OpenRouter
# OPENAI_API_KEY=sk-...             # прямой OpenAI
```

Основные поля `config.yaml`:

| Ключ | Что это |
|---|---|
| `api_base_url` | Роутер: `https://routerai.ru/api/v1`, `https://openrouter.ai/api/v1`, `https://api.openai.com/v1`, … |
| `api_key_env` | Имя переменной окружения с ключом (сам ключ — только в `.env`) |
| `model_claimant_lawyer` / `model_defendant_lawyer` / `model_judge` | Модели по ролям — могут быть разными |
| `jurisdiction` | Строка юрисдикции для промптов: «Российская Федерация, гражданское право», «РФ, арбитражный процесс»… |
| `max_rounds` | Максимум раундов прений (по умолчанию 3) |
| `max_context_tokens` | Лимит контекста дела; при превышении материалы суммаризируются LLM |
| `llm_params` | Доп. параметры запроса, передаются роутеру «как есть» (см. ниже) |

**Ускорение reasoning-моделей.** Модели вроде GLM тратят основное время на скрытые
«размышления». Замер на реальном прогоне: базовый вызов — 87 с, с настройкой ниже —
15–22 с (в 4–6 раз быстрее):

```yaml
llm_params:
  max_tokens: 4000          # не ставьте меньше объёма вердикта (~600-1000 слов)
  reasoning: {"effort": "low"}
```

## Материалы дела

- **`case_context.md`** (обязателен) — промпт-контекст: суть спора, стороны, позиции,
  что должно решить судье. Шаблон — `case_context.md.example`.
- **`case_files/`** — документы: **PDF** (pypdf), **DOCX** (python-docx, включая
  таблицы), **TXT/MD**. Неподдерживаемые форматы пропускаются с предупреждением.
  В репозитории оставлено демонстрационное дело (потребительский спор по ЗоПП) —
  замените на своё.

Все фрагменты попадают в контекст с пометкой источника
(`--- Источник: case_files/dogovor.docx ---`); агенты обязаны ссылаться на факты
в формате `[case_files/файл]`.

## Запуск

```powershell
python -m src.main run                     # полный прогон по config.yaml
python -m src.main run --max-rounds 1      # быстрый прогон (1 раунд)
python -m src.main run -q                  # без стриминга текста реплик
python -m src.main run -v                  # подробные логи (роль/модель/роутер каждого вызова)
python -m src.main config                  # показать конфигурацию без секретов
```

Реплики стримятся в консоль по мере генерации; по завершении создаётся протокол
`output/verdict_<ГГГГММДД-ЧЧММСС>.md`: параметры симуляции, выжимка дела,
реплики по раундам с авторами и итоговое решение судьи.

## Структура проекта

```
├── config.yaml.example   # шаблон конфига (роутер, модели, юрисдикция, лимиты)
├── .env.example          # шаблон секретов (ключ API)
├── requirements.txt
├── case_context.md.example / case_context.md
├── case_files/           # документы дела (PDF/DOCX/TXT/MD)
├── output/               # итоговые протоколы verdict_<timestamp>.md
└── src/
    ├── config.py         # загрузка и валидация конфига (.env + config.yaml)
    ├── llm_client.py     # универсальный клиент, модель по роли, стриминг, логи
    ├── document_loader.py# чтение case_files + case_context, лимит/суммаризация
    ├── agents/           # base, claimant_lawyer, defendant_lawyer, judge
    ├── graph.py          # LangGraph: узлы, условные переходы, run_debate()
    ├── report.py         # markdown-протокол output/verdict_<timestamp>.md
    └── main.py           # typer-CLI: run / config
```

## Ограничения MVP

- Только CLI и файлы: без веб-интерфейса, авторизации и базы данных.
- Без RAG/эмбеддингов: конкатенация материалов + LLM-суммаризация при превышении лимита.
- Юрисдикция влияет только на системные промпты; встроенной базы законов нет
  (следующая итерация — интеграция с внешним источником норм права, например
  MCP-сервер с законодательством РФ).
- Качество прений зависит от выбранной модели; судья — обычная LLM, а не
  арбитражный орган 🙂
