# Судебный симулятор (court-simulator)

Текущая версия: **v0.6.0** · [История изменений](CHANGELOG.md) · [Архитектура](docs/ARCHITECTURE.md) · [API](docs/API.md) · [Для разработчиков](docs/DEVELOPMENT.md) · [Отчёт по спринту (этап 3)](docs/SPRINT_REPORT.md)

Веб-приложение для **подготовки к судебному спору на этапе досудебной претензии**:
пользователь описывает ситуацию и загружает документы, три LLM-агента — **юрист
заявителя**, **юрист ответчика** и **судья** — ведут прения по делу в несколько
раундов, судья выносит мотивированное решение, а ИИ-аналитик готовит **блок
рекомендаций** для выбранной пользователем стороны: сильные/слабые места позиции,
риски в суде и правки текста ответа на претензию.

Оркестрация — **LangGraph** (state machine; судья-супервизор решает, когда прения
заканчиваются). Ссылки на нормы права **подтверждаются официальным порталом
pravo.gov.ru** через MCP-сервер `pravo-mcp` — модель не выдумывает реквизиты
актов. Backend — FastAPI + WebSocket, frontend — Next.js, всё локально на машине
пользователя. LLM — любой [OI]-совместимый роутер (routerai.ru, OpenRouter,
LiteLLM, vLLM, [OI]), модель выбирается отдельно для каждой роли.

## Быстрый старт для пользователя

1. Установите **Python 3.11+** (https://www.python.org/downloads/) и **Node.js
   LTS** (https://nodejs.org/).
2. Скачайте проект (Code → Download ZIP, распакуйте) или `git clone`.
3. Дважды щёлкните **`install.bat`**. Скрипт создаст окружение, поставит
   зависимости, соберёт фронтенд, спросит ссылку роутера и ключ API (можно
   пропустить клавишей Enter — заполните потом в веб-форме), запустит серверы и
   откроет браузер на `http://localhost:3000`.
4. В интерфейсе: **Настройка** → **Загрузка дела** → прения в **прямом эфире** →
   **Итог**: решение судьи и выделенный блок рекомендаций. Отчёт скачивается
   (.md) или печатается в PDF.

Повторный запуск — снова `install.bat` (переустановки не будет) или вручную:

```powershell
# окно 1 — бэкенд
.venv\Scripts\python.exe -m uvicorn src.api:app --host 127.0.0.1 --port 8000
# окно 2 — фронтенд
cd web; npm run start
```

CLI остался как debug-режим разработчика: `python -m src.main run [--max-rounds N] [-v]`.

## Как это работает

```
START → init → build_evidence_pack → claimant_turn → defendant_turn
                    → judge_review ──┬─ (ПЕРЕКВАЛИФИКАЦИЯ, ≤ 2 раз) ──→ build_evidence_pack
      ↑ ── (судья: ПРОДОЛЖАТЬ и раунды < max) ──────┤
                                                    └─→ final_verdict
                                                          → recommendations → END
```

- **init** — загрузка конфига и материалов дела, подготовка состояния.
- **build_evidence_pack** — правовое исследование (этап 3): из материалов дела
  извлекаются правовые вопросы, провайдеры (pravo.gov.ru, vsrf.ru, веб-поиск
  sonar) находят нормы и документы, пользовательские судебные акты
  классифицируются; собирается **Evidence Pack** с честными статусами
  верификации — единый для всех трёх ролей. При переквалификации дела судьёй
  собирается заново.
- **claimant_turn / defendant_turn** — реплики юристов: каждый видит всю историю
  прений, опирается только на факты из материалов дела и источники Evidence Pack
  (со ссылками [LAW-XXX]).
- **judge_review** — судья *не спорит*: оценивает аргументы и решает — задать
  уточняющий вопрос стороне/сторонам (машиночитаемый маркер
  `=== РЕШЕНИЕ СУДЬИ: ПРОДОЛЖАТЬ (кому: …) ===`), объявить **переквалификацию**
  (`ПЕРЕКВАЛИФИКАЦИЯ: <новый характер спора>` — например, выяснилось, что товар
  использовался для извлечения коммерческой прибыли и ЗоЗПП неприменим:
  нормативная база собирается заново, максимум 2 раза) или завершить процесс
  (`ЗАВЕРШИТЬ`). `max_rounds` — жёсткий предохранитель.
- **final_verdict** — мотивированное решение + **linter правовых ссылок**: все
  упоминания статей/актов сверяются с Evidence Pack; непроверенные убираются
  (repair-pass) или помечаются в отчёте.
- **recommendations** — ИИ-аналитик готовит блок рекомендаций для стороны,
  выбранной пользователем: сильные стороны, слабые места, риски в суде, правки
  текста ответа на претензию и качественный прогноз (высокие/средние/низкие);
  тоже проходит linter ссылок.

**Подтверждение норм права.** Реквизиты актов (номер, дата, ссылка на официальную
публикацию) подтверждает pravo.gov.ru; тексты статей добираются через внешний
источник и помечаются как неофициальные. Если источники недоступны — симуляция
продолжается в деградировавшем режиме: агенты получают инструкцию не утверждать
точные нормы, а в отчёте появляется предупреждение о ручной проверке. Подробности
— в разделе «Правовые источники и надёжность ссылок» ниже.

Юрисдикция из настроек подставляется во все системные промпты; для РФ это ГК РФ,
ГПК/АПК и профильные законы с прямым запретом выдумывать номера статей. Каждое
обращение к LLM логирует роль, модель и роутер.

## Настройка

Для CLI/отладки: скопируйте `.env.example` → `.env` (ключ API) и
`config.yaml.example` → `config.yaml` (роутер/модели/юрисдикция).
Для веба всё то же задаётся на первом экране интерфейса — файлы не нужны.

В `.env` положите ключ (имя переменной должно совпадать с `api_key_env` в конфиге):

```ini
ROUTERAI_API_KEY=sk-...             # routerai.ru
# OPENROUTER_API_KEY=sk-or-v1-...   # OpenRouter
# OPENAI_API_KEY=sk-...             # прямой OpenAI
```

Основные поля `config.yaml`:

| Ключ | Что это |
|---|---|
| `api_base_url` | Роутер: `https://routerai.ru/api/v1`, `https://openrouter.ai/api/v1`, `https://api.openai.com/v1`, … |
| `api_key_env` | Имя переменной окружения с ключом (сам ключ — только в `.env`) |
| `model_claimant_lawyer` / `model_defendant_lawyer` / `model_judge` | Модели по ролям — могут быть разными |
| `jurisdiction` | Строка юрисдикции для промптов: «Российская Федерация, гражданское право», «РФ, арбитражный процесс»… |
| `max_rounds` | Максимум раундов прений (по умолчанию 3) |
| `max_context_tokens` | Лимит контекста дела; при превышении материалы суммаризируются LLM |
| `llm_params` | Доп. параметры запроса, передаются роутеру «как есть» (см. ниже) |
| `legal_mcp` | MCP-поиск норм права: `enabled`, `command`, `limit` (по умолчанию включён) |

**Ускорение reasoning-моделей.** Модели вроде GLM тратят основное время на скрытые
«размышления». Замер на реальном прогоне: базовый вызов — 87 с, с настройкой ниже —
15–22 с (в 4–6 раз быстрее):

```yaml
llm_params:
  max_tokens: 4000          # не ставьте меньше объёма вердикта (~600-1000 слов)
  reasoning: {"effort": "low"}
```

## Материалы дела

- **Промпт-контекст** — суть спора, стороны, позиции, что должно решить судье:
  в вебе — текстовое поле на втором шаге; для CLI — файл `case_context.md`
  (шаблон `case_context.md.example`).
- **Документы** — **PDF** (pypdf), **DOCX** (python-docx, включая таблицы),
  **TXT/MD**: в вебе — зона drag-and-drop; для CLI — каталог `case_files/`.
  Неподдерживаемые форматы отклоняются с указанием причины.

Все фрагменты попадают в контекст с пометкой источника
(`--- Источник: dogovor.docx ---`); агенты обязаны ссылаться на факты
в квадратных скобках по имени файла.

→ итог с рекомендациями. Отчёт также сохраняется в `output/verdict_<timestamp>.md`.

CLI (debug-режим разработчика):

```powershell
python -m src.main run                     # полный прогон по config.yaml
python -m src.main run --max-rounds 1      # быстрый прогон (1 раунд)
python -m src.main run -q                  # без стриминга текста реплик
python -m src.main run -v                  # подробные логи (роль/модель/роутер каждого вызова)

```

Реплики стримятся в консоль; по завершении — протокол `output/verdict_<timestamp>.md`
с таблицей потребления ресурсов.

## Правовые источники и надёжность ссылок (этап 3)

**Ключевое правило**: ИИ не выдаёт юридическую ссылку как подтверждённую, если она
не пришла из проверяемого источника и не присутствует в Evidence Pack.

### Архитектура источников

- **pravo.gov.ru** (официальный портал публикации, приоритетный) — подтверждает
  реквизиты актов: номер опубликования, дату, официальную ссылку. Текст — скан PDF,
  поэтому текст статьи добирается через внешний источник.
- **КонсультантПлюс** (тексты статей) — машиночитаемый текст нормы; помечается
  как неофициальный источник, сверять с официальной публикацией.
- **vsrf.ru** (официальный сайт ВС РФ) — постановления Пленума, обзоры судебной
  практики, опубликованные документы раздела (уровень авторитетности A).
- **Материалы дела пользователя** — судебные акты, которые вы загрузили, помечаются
  уровнем `USER`: они не считаются внешне подтверждёнными до сверки.

### Как запускать диагностику источников

```powershell
python -m src.legal_diagnostics              # полная проверка цепочки pravo-mcp
python -m src.legal_diagnostics --json       # машиночитаемый вывод
python -m src.legal_diagnostics mock --query 309   # smoke-тест без сети (фикстуры)
```

Код возврата 1 при наличии проблем — удобно для CI. Также доступны API:
`GET /api/legal/health`, `POST /api/legal/diagnostics`,
`GET /api/session/{id}/evidence` (Evidence Pack сессии).

### Как трактовать статусы источников

| Статус | Значение | Можно ли цитировать точно |
|---|---|---|
| `verified` | реквизиты + точная выдержка из внешнего источника | да |
| `partially_verified` | реквизиты подтверждены, текст получен из неофициального источника или недоступен | только с оговоркой |
| `unverified` | источник не подтверждён внешней проверкой (например, загружен пользователем) | нет |
| `contradicted` | источник противоречит другим данным | нет |
| `unavailable` | провайдер недоступен | — |

Уровни авторитетности судебной практики: **A** — КС РФ, Пленум ВС РФ, обзор
практики ВС РФ; **B** — ВС РФ, кассационные суды; **C** — апелляционные суды;
**D** — первая инстанция; **USER** — акт загружен пользователем, реквизиты
внешне не подтверждены. Судебную практику симулятор никогда не называет
нормой права — только «имеется сходная практика», «может поддерживать аргумент».

### Проверка правовых ссылок

Вердикт и рекомендации проходят linter (`src/legal/citation_verifier.py`):
упоминания `ст. N`, номеров актов (`266-ФЗ`), номеров дел и `[LAW-001]`
сверяются с Evidence Pack. При проблемах выполняется один repair-pass (LLM
убирает непроверенные ссылки), остатки ошибок показываются в разделе отчёта
«Проверка правовых ссылок».

### Как сообщать об ошибках источников

Ошибки сети/парсинга источников не роняют симуляцию: провайдер возвращает
честный статус (`unavailable`/`degraded`) и понятное сообщение; секреты
(API-ключи) никогда не попадают в логи, статусы или отчёты. Полная диагностика
— `python -m src.legal_diagnostics` или `POST /api/legal/diagnostics`.

## Ограничения

- Однопользовательский локальный инструмент: без авторизации и внешней БД;
  сессии живут в памяти и сбрасываются при перезапуске бэкенда.
- Без RAG/эмбеддингов: конкатенация материалов + LLM-суммаризация при превышении лимита.
- MCP-источник подтверждает **реквизиты** норм (номер, дата, ссылка на официальную
  публикацию) и покрывает только федеральные НПА РФ; тексты статей — сканы PDF,
  машиночитаемый текст добирается из внешнего источника и помечается как
  неофициальный. API портала неофициальный и может меняться.
- Судебная практика: массовый программный поиск по нижестоящим судам НЕ
  выполняется (sudact.ru требует JavaScript, kad.arbitr — капча). Ищутся
  документы раздела Пленума/обзоров на vsrf.ru и, при включённом веб-поиске
  (`legal_research.web_search`), результаты поисковой модели роутера
  (Perplexity Sonar) — они всегда помечены «требует сверки по официальному
  источнику» и проходят linter ссылок; ваши собственные акты из материалов
  дела учитываются с уровнем `USER`.
- Переквалификация дела судьёй ограничена 2 раза за процесс
  (`MAX_REQUALIFICATIONS`); каждый повторный сбор Evidence Pack —
  дополнительные вызовы провайдеров и поисковой модели (видно в таблице
  потребления).
- Качество прений зависит от выбранной модели; результат — информационно-
  аналитическая симуляция для подготовки к спору, не юридическое заключение
  и не замена проверки квалифицированным юристом 🙂

## Диагностика проблем (FAQ)

| Симптом | Причина и решение |
|---|---|
| Красная плашка «Бэкенд не отвечает» в шапке | Сервер API не запущен: выполните `install.bat` или запустите окно бэкенда вручную (см. «Запуск»). Индикатор позеленеет сам. |
| Интерфейс ведёт себя «по-старому», фикс не помог | Устаревший бандл: `next start` раздаёт собранное на момент старта. Пересоберите (`cd web; npm run build`) и перезапустите окно фронта; сверьте версию в футере страницы. |
| «Не удалось связаться с бэкендом…» при действиях | То же, но в момент запроса: проверьте окно «court-sim backend» и перезагрузите страницу. |
| Ключ API: «слетел» / требует в форме | Ключ хранится в `.env` (`ROUTERAI_API_KEY`), форма может оставаться пустой — бэкенд подставит ключ сам. Маска видна в карточке конфигурации. Перезапуск бэкенда сессии не восстанавливает (они в памяти) — создайте сессию заново. |
| Выбор файлов «по одному» | Обновитесь до v0.2.2+ (был баг инвалидации FileList); проверьте версию в футере. |
| Вызов «Остановить» не мгновенный | Остановка кооперативная — текущая реплика доигрывается (15–90 с), затем граф корректно завершается. |
| В таблице потребления цена «—» | Роутер не отдал прайс для этой модели (известный кейс — `~anthropic/*` без имени в каталоге routerai). Токены при этом считаются. |
| Прения идут медленно | Причина почти всегда в модели: тяжёлые/reasoning-модели (Qwen-max, Kimi, Claude) генерируют заметно дольше дешёвых. Для черновиков берите GLM Flash; ускорение reasoning — `llm_params` выше. |
| `install.bat` ругается на Python/Node | Установите Python 3.11+ и/или Node.js LTS по ссылкам из «Быстрого старта» и запустите снова. |

## Дорожная карта

Идеи следующих итераций (по убыванию ценности):

1. **Тексты НПА** — `get_npa` у портала стабильно 404; восстановить цитирование статей
   (альтернативный источник или их починка API) — главный пробел достоверности.
2. **Скачивание и разбор PDF, найденных веб-поиском** — сейчас sonar возвращает
   ссылки и выдержки; full-text сверка реквизитов подняла бы часть источников
   до `verified`.
3. **Отдельная модель аналитика** — четвёртый слот роли (рецепт в DEVELOPMENT.md).
4. **SQLite-персистентность сессий** — переживать перезапуск бэкенда, история прогонов.
5. **Нативный tool calling** для сильных моделей (сейчас — детерминированный
   промежуточный шаг, работающий на любых моделях).
6. **docker-compose** — запуск одной командой на любой ОС.
7. **RAG по документам дела** — если дела вырастут за пределы контекста.

Подробности реализации и точек расширения — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)
и [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md).
